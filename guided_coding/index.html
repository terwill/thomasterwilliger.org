Guided Coding for Claude Code

A structured way to plan, test and review code changes with an LLM.

Describe the change you want. Guided Coding helps Claude prepare a plan, implement it, check the result and obtain outside feedback. You keep the decisions about the plan, integrating the result and publishing it.

This download contains the complete Guided Coding procedure, checking tools and general project defaults. Keep one central copy and use it in your own Git repositories, with separate settings for each project.

Source and adaptations. The material comes from cctbx_project/libtbx/guided_coding. The packager edits the documentation and local path examples to use ~/Downloads/GuidedCoding/guided_coding, generalizes project-specific wording and examples, and supplies a general defaults card for your own projects. Checking tools and the Developer–Guide Contract are unchanged; the license, and which files were adapted with their checksums before and after, are recorded with the download.

1. Get Claude Code ready

Use a local Claude Code session. These instructions cover the Claude app on a Mac and Claude Code in Terminal on macOS or Linux. This installation is stored on your computer; it is not available in a cloud session.

You also need Git, Python 3.10 or newer, Bash and shasum. Check git --version and python3 --version in Terminal. If needed, use the official Git and Python installation instructions.

Choose your route. If you will use an API key, follow the Terminal option below. If you will use the Claude app with your account, follow the app option.

Claude app on a Mac

If you already have the app, choose Claude → Check for Updates, then quit and reopen it. Otherwise download Claude for Mac and install it.

Sign in with an account that includes Claude Code: Pro, Max, Team or Enterprise. Use the Code tab and choose Local. The app includes Claude Code; a separate Terminal installation of claude is not required.

Claude Code in Terminal

If Claude Code is not installed, enter these lines one at a time. Wait for installation to finish before the second line:

curl -fsSL https://claude.ai/install.sh | bash
export PATH="$HOME/.local/bin:$PATH"

Check with claude --version. Guided Coding requires 2.1.281 or newer. For a native installation, update with claude update; use your package manager if you installed it that way.

You can sign in with your Claude account, or use your own API key supplied in ANTHROPIC_API_KEY. For an API key, keep using the Terminal window where the key is set. API usage is billed to that key’s API account. See Anthropic’s authentication instructions.

2. Download and keep the kit in one place

  1. Download guided_coding.zip into your Downloads folder.
  2. Before unzipping, check that it matches this page. In Terminal, run the command below. It should end with guided_coding.zip: OK; stop if it does not.
cd ~/Downloads && printf '%s  guided_coding.zip\n' '661f0e0e40e70ec34b3013f5dc45c31d950b4622741724d99c70e0e444feaa51' | shasum -a 256 -c -

Double-click the ZIP to unzip it in Downloads. Keep the resulting GuidedCoding folder there: Claude will use ~/Downloads/GuidedCoding/guided_coding as the central procedure for your projects. If you choose another stable location, change the path in the next message.

3. Register Guided Coding once

Open an ordinary local Claude Code session. In the app, use Code → Local. In Terminal, run claude. Send this message and let Claude finish:

Registration creates a personal link, normally ~/.claude/skills/guided_coding, to the verified kit. One registration covers projects in that Claude Code configuration. It does not start a coding task.

4. Set up your own project

  1. Open a new local Code session in the Git repository you intend to change. In the app, select that folder. In Terminal, cd to it before running claude.
  2. Enter /guided_coding help to confirm the command is available.
  3. Download the general developer card, attach it in that session and send /guided_coding setup.
  4. Check the proposed project settings and instruction changes. Approve them when they are right, then let Claude finish saving and checking them.

The card asks Claude to discover your project’s environment, build and test commands from its documentation and saved settings. It supplies no project-specific commands, server names or private paths. Remote work can be deferred when it is not needed.

Setup is for the repository you selected. Other repositories or checkouts may need their own setup. Keep any existing project instructions and work.

5. Start a guided coding task

Open a new local Claude Code session in the configured repository. Send /guided_coding followed by your task, requirements and any bug report as one message. For example:

/guided_coding Describe the change you want to make, your requirements, and how you would check the result.

If you paste a bug report, put it below the command before sending the message. A bug report sent by itself can start ordinary Claude Code work before Guided Coding is involved.

  • Plan. Check the proposed goal, scope, tests and limits. Approve or revise the plan.
  • Work and checks. Claude implements the agreed change and reports the tests and other checks. Approve tool requests when they are reasonable. Auto mode can reduce routine prompts when available.
  • Outside review. When asked, attach both reviewer files—the message and review package—to a separate capable LLM chat, preferably with a different LLM. Write please review this package, then paste the complete review back into the guided session.
  • Result. Read the summary, checks and limits. Decide whether to integrate, revise or discard the result.
  • Publication. Publishing is a separate decision. If you want local work only, include do not publish in your task. Check the closeout summary for local changes and commits.

If you need help understanding a decision, give the relevant text to a Guided Workflow Helper. You can redirect or stop the coding session at any time.

Help and updates

Guided Coding control commands
CommandWhat it does
/guided_coding helpExplain the available commands.
/guided_coding statusRead the source, registration and project setup status.
/guided_coding historyList the project’s recorded tasks.
/guided_coding setupRecover settings and propose needed project setup.
/guided_coding uninstallRemove only the verified personal link, leaving source and project records.
The command is missing or the wrong kit is loaded

Open a fresh local session after registration. Check that the personal link points to the folder you intended and that no competing project skill is selected. Use /guided_coding status. Ask Claude to inspect a conflicting link or directory before changing it.

The client version is too old, or the version says NOT CHECKED

Update the client you are using and start a new session. The minimum engine version is 2.1.281; this differs from the app version shown in About Claude.

In app sessions, the checker uses the app’s own engine. When it cannot read that version, it prints NOT CHECKED and continues; this does not confirm that the minimum was met. Terminal sessions still check the claude command on PATH.

Update the Guided Coding kit

Finish active guided tasks. Download and verify the new ZIP, then extract it into a separate folder. Ask Claude to verify the new source and inspect the existing registration before changing the link. Keep the old folder until the new registration is checked, then open a fresh session.

Do not edit the verified guided_coding subfolder or put extra files inside it. Your project settings and records live in your project, outside that source kit.

Stop and undo this task

Tell Claude:

Stop this task and restore the project to its state before this task started. Preserve any work that was already present.

For the maintainer: rebuild this download

The generator lives beside the package in the website repository. From the website checkout, run:

python3 guided_coding/build_package.py

It fetches the procedure source, pins one commit, verifies it and runs the tests. It adapts the documentation and examples for this general edition, creates its own source manifest and checks that edition too. It then writes the ZIP, checksum, metadata, this page and all documentation pages locally. Review the changes before committing and pushing. See the maintenance instructions and package metadata.
