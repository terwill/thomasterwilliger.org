# Guided Coding setup card: a general software project

Supply this card with `/guided_coding setup` in the Git repository you intend
to change. It proposes settings; your project's existing instructions and
your decisions determine the actual method.

Use the project's own documentation, configuration, scripts and saved
settings to discover how it works. Recover existing values before asking
me to supply them. Ask only for missing information that affects the work.

Establish:

- The intended repository, related repositories and existing instructions.
- The shell, interpreter or compiler, dependency/environment activation,
  and actual build and test commands with their working directories.
- Targeted tests and the project's policy for wider tests, review,
  integration and publication. Do not assume a universal test command.
- Suitable temporary work locations and durable records/results.
- Relevant hooks and safeguards; keep them enabled.
- Remote servers, CI and resource limits only if this project needs them.
  Recover its actual values; otherwise mark the items deferred or not applicable.

Show the complete proposed project-method and instruction changes before
saving them. Let me make any decisions that are still needed. After an
approved save, verify it and report unresolved items. Setup alone must
not start a coding task, connect to a server, or publish work.

This card supplies no private paths, accounts, API keys, server allocations
or permissions. It does not replace the Guided Coding procedure.
